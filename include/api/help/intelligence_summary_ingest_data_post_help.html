Overview

Ingests or resumes summary data processing for a specific record, optionally forcing ingestion after a delta timeout.

Summary

This endpoint handles ingestion of summary data for modules that require complex or bulk processing. It supports first-time ingestion, delta ingestion (update on changes), and forced ingestion for stalled or timed-out records. Background scheduling is used when applicable. This process ensures summary content is generated, updated, and synchronized correctly. If the optional force flag is set to true, the system will clear any stalled or timed-out records and re-initiate ingestion.

Request Arguments

Name Type Description Required
module string Name of the module True
recordId string ID of the record requiring summary ingestion True
force boolean Optional. If set to true, forces ingestion by clearing timeout/stalled entries and restarting the process. False

Request Example (Normal Ingestion)

POST /rest/v11/Accounts/abc123/intelligence/summary/ingest
{
    "module": "Accounts",
    "recordId": "abc123"
}

Request Example (Force Ingestion)

POST /rest/v11/Accounts/abc123/intelligence/summary/ingest
{
    "module": "Accounts",
    "recordId": "abc123",
    "force": true
}

Response Example (Normal Ingestion)

Error Handling

  • 401 Unauthorized: Returned if the user lacks access to the SummarizationGai module.
  • failedToIngestInitial: If initial ingestion fails, the summary is marked as deleted and an error is returned.
  • handleIngestState: Handles errors during delta ingestion based on summary state and returns fallback data if possible.
  • failedConfirmDataSent: If ingestion succeeds but the confirmation step fails, the summary is marked as errored and a warning is returned with any available data.
